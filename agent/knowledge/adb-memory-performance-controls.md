# AnyDeck 内存与后台性能控制

## 目标与范围

设备切页、长时间日志输出、大文件导入、连续截图及历史设备切换时，控制进程数量、短期分配和常驻缓存。涉及 Android ADB、HarmonyOS HDC 与 iOS go-ios；本次未改变界面样式或跨窗口协议。

## 数据与逻辑

| 流程 | 控制机制 | 生命周期边界 |
| --- | --- | --- |
| Logcat / hilog | `LogcatController` 的会话序号丢弃迟到启动结果；实时日志和待刷新队列各最多 3000 行，单行最多 16384 字符 | `IndexedStack` 中仅当前 Logcat Tab 采集；切页、切设备或销毁时终止进程 |
| 文件日志导入 | `File.openRead` + UTF-8 文本流；按行限长，只保留最近 3000 条 | 导入完成后一次发布结果；Provider 销毁后不发布 |
| Android / HarmonyOS 终端 | stdout/stderr 100 ms 合批；待发布最多 128 块，每块最多 32768 字符；已展示最多 1500 行，每行最多 16384 字符；命令历史最多 200 条 | 离开 Tab 时停止 Android shell 和正在执行的 HDC 命令，保留输出；返回后恢复 Android shell。唯一会话 ID 和会话序号阻止迟到进程挂回，关闭会话后移除序号 |
| 连续截图 | 一次只允许一个自动截图请求；上一张结束后再排下一次；过期请求在图片解码前丢弃 | 切页取消计时器并使在途请求失效；设备 Provider 无监听者后自动释放 PNG、`ui.Image` 和录屏资源 |
| iOS 设备发现 | 5 秒轮询有单次在途保护；CLI 回退 10 秒超时并杀进程 | Tracker 销毁后取消轮询，不再发布结果 |
| 应用包缓存 | 内存最多保留 12 个近期设备或连接通道 key；命中时刷新近期顺序 | 旧设备可从已有 SharedPreferences 缓存重新读取；清理设备缓存时移除对应内存与持久化条目 |

Logcat 和终端的内存上限均按条数与单条长度共同约束。截图控制器按设备隔离，`autoDispose` 仅在最后一个页面监听者离开后执行，因此当前 `IndexedStack` 中的预览仍可直接查看。

## 测试与回归影响

自动测试覆盖：长文件导入保留末尾、跨 chunk 超长行截断、终端历史上限、自动截图单次在途与图片释放、iOS 慢轮询不重入、历史设备缓存回读。

人工 Profile 验证路径：

1. 打开 Android Logcat 或 HarmonyOS hilog，切到其他 Tab，再切设备：确认旧 `adb logcat` / `hdc hilog` 进程退出，返回后只存在当前设备的一条采集进程。
2. 导入大日志文件并持续滚动终端输出：观察 RSS 峰值、UI 帧耗时和停止后的内存回落；确认末尾日志可搜索、终端旧输出仍可见。
3. 设置 1 秒连续截图，模拟截图耗时大于 1 秒，切页和切设备：确认没有并发截图进程、过期图片不显示。
4. 让 go-ios 发现持续超时，确认 5 秒 tick 不叠加新进程；连续浏览超过 12 个设备后回看旧设备应用列表。

静态测试不能证明 macOS RSS、GPU Texture 或真机 ADB/HDC 的实际峰值。SharedPreferences 中已有历史包数据仍由现有持久化机制维护；本次只限制解码后的内存列表数量。
