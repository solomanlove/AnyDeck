# AnyDeck 投屏白板本地标注

## 需求与入口

- 投屏右侧工具栏在截图入口附近展示画笔 icon。点击后进入白板模式，鼠标在实际视频画面内按下并拖动可绘制自由曲线；再次点击退出白板模式。
- 开启后展开颜色、撤销、清空三个操作。颜色沿用截图编辑的六种颜色；一笔是一次撤销单位，单击可留下圆点。
- 关闭白板模式后，已有笔迹继续显示；再次开启可继续绘制。清空只作用于当前投屏窗口。

## 技术方案

| 层 | 实现 | 原因 |
| --- | --- | --- |
| 入口 | `MirrorWhiteboardControls` 接入 Android/HarmonyOS 与 iOS 工具栏 | 共用中英文文案和窗口 Theme；操作区在画面之外，不遮挡演示内容 |
| 状态 | 每个 `MirrorWindowContent` 持有一个 `MirrorWhiteboardController` | 独立窗口及应用副屏互不串色、串笔迹；关闭窗口即释放 |
| 画布 | `MirrorWhiteboardCanvas` 覆盖实际 Texture，使用 `CustomPaint` 和 `RepaintBoundary` | 视频仍走 Rust/原生 Texture，Dart 只绘制笔迹，不复制视频帧 |
| 坐标 | 每个点按视频画面宽高归一化到 $[0,1]$ | 窗口缩放后保持相对位置；横竖屏方向变化时清空旧轨迹 |
| 输入 | 白板开启时拦截画面鼠标，并阻断 Viewer 发往设备的 touch、右键/中键、滚轮与键盘输入 | 绘制期间不误触手机；退出后恢复原控制逻辑 |

画布分别贴在 Android/HarmonyOS 的 `EmbeddedScrcpyTextureSurface`、iOS USB 的视频 Texture 与 AirPlay Texture 上。白板状态不进入 Riverpod 全局 Provider、不增加 ADB/HDC/WDA 命令，也不需要跨 Isolate MethodChannel。一次绘制最多保存 2048 个采样点，当前窗口最多保存 200 笔，避免长时间演示后内存无界增长。

## 使用边界

- 标注仅显示在电脑端投屏窗口，不写入手机屏幕。现有截图和录屏调用设备端采集，所以不会包含电脑端白板笔迹。
- 白板不在窗口之间同步，也不持久化；关闭投屏窗口后笔迹消失。Android 自动换线重建窗口内容时也会重置笔迹。
- 右侧工具栏白板开启期间保持可见，便于修改颜色、撤销和清空。全屏模式沿用现有隐藏工具栏行为，仍可在画面上绘制；要操作工具栏需退出全屏。

## 验证与回归

1. 在 Android、HarmonyOS、iOS USB 和 AirPlay 投屏窗口分别开启画笔，画线、点按、修改颜色、撤销与清空；确认手机内容没有响应白板绘制。
2. 退出白板后测试点击、拖拽、右键返回、滚轮及键盘输入；确认控制恢复。白板开启时确认这些输入不会操作手机。
3. 缩放窗口与切换设备横竖屏，检查笔迹对齐及旧轨迹清理；分别检查 Light/Dark、中英文、窄工具栏与自动隐藏设置。
4. 关闭并重开窗口、Android USB/TCP 自动换线、iOS USB/AirPlay 切源，确认白板状态与笔迹按当前窗口生命周期回收。

自动测试覆盖落笔、撤销、清空、颜色、点位裁剪、容量限制、方向切换和鼠标命中；Flutter 定向 analyze 与相关 Widget 测试通过。真机上的四种投屏路径和高帧率绘制流畅度仍需人工验收。
