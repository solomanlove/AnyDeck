# AnyDeck Flutter 测试隔离与异步回归

## 需求与修复范围

2026-11-18：在 Flutter stable 3.50.0 下继续处理工具链迁移时发现的失败与挂起测试，保留已有无关修改，验证后单独提交。开发命令以 [DEVELOPMENT.md](../../DEVELOPMENT.md) 为准。

原失败在旧 SDK 对照中也能复现，不能仅靠升级 SDK 解决。修复覆盖当前 UI 契约、测试依赖隔离，以及测试暴露的实际生命周期与布局问题。

## 失败原因与处理

| 问题 | 修复与回归 |
| --- | --- |
| 设备行不再依靠双击与一排图标按钮，旧 finder 找不到入口 | 使用设备稳定 key、真实列表主操作及 `DeviceContextAction` 菜单；检查编辑不触发导航、三平台共享/无线操作权限与禁用态 |
| 导航图标、诊断入口、主题与 AirPlay 文案已变化 | 对齐 `AppNavigationIcons`、全局诊断真实控制器及当前主题语义；保留点击、检测调用次数、换色不重复检测、中英文与平台安装引导断言 |
| Widget test 中启动真实 CLI、网卡、注册表与设置初始化 | `dashboard_test_environment.dart` 只替换平台初始化；诊断探针使用可计数结果；共享服务使用内存存储并显式释放 |
| 侧栏概览缓存 IO 和启动层 hold 在 FakeAsync 内无法自行推进 | 导航测试注入概览快照，明确推进启动 hold；工具内容的极窄边界单独装配组件，不混入外壳导航和平台启动 |
| 概览读取缓存前尚未订阅在线 Tracker，首帧快照会被自动释放 | 首次 await/yield 前订阅在线依赖；使用缓存 gate 和真实事件流验证读取期间的在线快照不会丢失 |
| UDP `close()` 返回时端口尚未真正释放 | 等待流的 done；停止发布只等待本次关闭的监听，重启先等待旧监听释放，覆盖独占重绑、启动中关闭和并发重启 |
| 追加发送测试忙轮询等待 IPC | mock IPC 用 Completer 通知实际调用，不再通过零延迟循环猜测完成时机 |
| 摄像头版本拒绝和取消测试在构造服务时隐式加载 Rust 动态库 | 显式注入既有 `BridgeFake`，断言未启动原生会话；在提交快照中复现隐式依赖，避免本机产物掩盖新电脑/CI 失败 |
| DAL/定时任务集成测试明确要求真实 Rust 动态库 | 全量测试前使用仓库脚本从源码编译固定工具链的库，CI 和开发说明同步该前置步骤；不将原生集成用例改成跳过或伪造可用状态 |
| WDA 测试将正常握手和故障都压在 250ms 调度窗口内 | 真实 HTTP 调度预算设为 2s，假服务故障延迟设为 10s；继续验证健康 Session 不重放输入，失效 Session 清除 ready，不修改生产超时 |
| 批量脚本只筛选 Android，误排除既有 HDC 执行能力 | 允许在线 Android/HarmonyOS，继续排除 iOS；覆盖 ADB/HDC 路径、完整参数和 iOS 禁用 |
| 概览 160px 内容发生 RenderFlex 溢出 | 标题使用可伸缩宽度，电量和 Root 状态允许换行；保留窄屏渲染及明暗主题测试 |
| Meitu 无条件当作 Xiaomi，与 manufacturer 回退约定冲突 | 移除全局 Meitu 别名，继续按真实 manufacturer 回退；Xiaomi 图标断言对齐 SVG 资源 |

## 测试维护约定

- 组件测试隔离系统边界，业务控制器、路由、状态变化与断言继续真实执行。不要用跳过、吞异常或删除业务断言让测试通过。
- 真实 IO 在 `tester.runAsync` 中推进；FakeAsync 下只等待由测试可控制的 Future，释放资源时先卸载 Widget/Provider 订阅，再关闭服务。
- 模态框背后仍有 busy 动画时，只推进所需转场，不用 `pumpAndSettle` 等待永不停止的动画。
- HTTP 超时故障必须明显超过正常调度预算；不要把并行测试机器的瞬时负载当作协议故障。
- macOS Release 的 arm64/Intel 两个 job 均执行静态分析和全量 Flutter 测试，再执行脚本回归与构建。远端 CI 是否通过需以实际 workflow 结果为准。
